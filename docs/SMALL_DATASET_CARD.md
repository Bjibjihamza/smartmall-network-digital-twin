## Leakage review (quantified)

- **Interface state** (fault_active := any interface admin_up==0 or carrier==0): true positives 288, false positives 0, recall on admin-mechanism faults 1.0. `admin_up`, `carrier`, `oper_up` are classified `mechanism_revealing` and excluded from default model inputs.
- **Localisation from admin state**: exact target recovered in 288/288 admin-mechanism fault windows. Any localisation result using these columns measures the injection mechanism, not realistic diagnosis.
- **window_id** deterministically encodes the phase in v2 (`w01–w03` healthy, `w04–w06` failed, `w07–w09` recovered): 01->healthy: 147, 02->healthy: 147, 03->healthy: 147, 04->failed: 147, 05->failed: 147, 06->failed: 147, 07->recovered: 147, 08->recovered: 147, 09->recovered: 147. It is an identifier, never a feature.
- `experiment_id`, `campaign_id`, timestamps, `run_seed` and `raw_relative_path` are identifiers; `scenario_key`, `fault_*`, `param_*`, `phase`, `expected_unreachable_pairs` are ground truth.
- `offered_mbps` is an experimental *condition* (constant per run); use only if the deployment would know the load profile.
- `tc_samples.csv` configured parameters (`cfg_*`) exist only in raw data and are never exported.

## Splitting policy

- Unit = independent experiment. Folds 1–3 = leave-one-repetition-out within each (protocol, scenario, load) stratum; every stratum appears in every fold.
- Never split windows or rows of one experiment across train/test.
- v1 (`small_link_v1`: sequential probes, 2 packets, no traffic/tc telemetry, variable window length) and v2 rows differ in protocol; train/test on mixed protocols only with protocol as an explicit covariate.
